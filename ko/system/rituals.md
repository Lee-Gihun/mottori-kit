# 세션 의식과 규약 (조건부 로드)

상시 규칙 일곱 개는 `AGENTS.md`에 있다. Claude는 `CLAUDE.md`의 `@AGENTS.md` 한 줄로 같은 파일을 읽는다.
이 문서는 아래 상황이 왔을 때 해당 절만 읽는 상세 규약이다. 조건부 로드의 원칙은
[기억 선택 계약](PRD-session-memory.md#retrieval)을 따른다. 이 문서는 킷이 따로 썼고, 데이터 경계 절은
인스턴스마다 방향이 다르다.

**어느 상황에 어느 절을 읽나**

- 세션 시작, 재개, 압축 직후: [세션 진입과 복구](#entry). 결정이나 국면 변화를 기록할 때: [결정과 사건 기록](#events).
- 일을 다른 세션이나 다른 런타임이 이어 갈 때: [일을 넘기기](#handoff).
- 주인에 대한 사실을 단언하거나 고칠 때: [개인 사실](#facts).
- 파일을 새로 만들거나 재편한 뒤: [산출물 뒤 점검](#after-output)과 [파일 규약](#files).
- 저장소 밖 사람이 읽을 글: [외부 문안](#outbound). 밖에서 자료를 들여올 때: [데이터 경계](#boundary).
- 렌즈를 쓸 때: [사고렌즈](#lenses). 브라우저로 업무·금융 사이트를 다룰 때: [브라우저](#browser). 회상과 `/garden`: [기억 시스템](#memory).

<a id="entry"></a>
## 세션 진입과 복구

- SessionStart 훅이 상태를 주입한다(`AGENTS.md` 규칙 2). 주입이 안 왔으면 훅이 실패한 것이다.
  `python3 tools/doctor.py`로 진단하고 두 NOW 파일을 직접 함께 읽는다.
  *(Why: 훅은 실패해도 세션을 막지 않도록 만들어져 조용히 죽는다. 아무 주입이 없다는 것을 "새 소식 없음"으로 읽지 않는다.)*
- **장기 작업을 넘겨받을 때는 그 작업의 `HANDOFF.md`부터 읽는다.** 진행 수치는 대화가 아니라 그 작업의
  상태 도구에서 가져온다. *(Why: 대화의 수치는 압축되면 사라지거나 낡는다. 디스크의 도구는 지금 값을 다시 센다.)*
- 압축 직후에는 요약이 말하는 상태와 깊이를 NOW, journal, 서류철로 확인하기 전까지 잠정으로 둔다.
- 압축 뒤 처음 파일을 읽고 나면 지금 어느 절차의 어느 단계에 있고 다음에 허용되는 단계가 무엇인지
  한 줄로 적는다. 알 수 없으면 `미측정`이라고 적는다. 시험 중인 규칙이다.
  *(Why: 압축 뒤 에이전트가 절차상 위치를 잃는다는 보고가 있다. 논문 2609.09153 §3.2.)*

<a id="handoff"></a>
## 일을 다른 세션이나 런타임에 넘기기

일이 다른 곳에서 이어질 때 쓴다. 새 세션, 다른 런타임, 지금 옆에서 돌고 있는 세션이 모두 해당한다.

- 멈추기 전에 넘김 메모를 쓴다: `_private/state/handoff/<YYYY-MM-DD-HHMM>-<주제>.md`. 다섯 부분이다.
  1. 주인이 청한 것. 주인의 말 그대로.
  2. 일이 어디까지 왔나. 끝난 것, 안 끝난 것, 확인하지 못한 것.
  3. 이 세션에서 정한 것과 그 이유.
  4. 이 대화 안에만 있고 건너가야 하는 것. 답, 초안, 목록. 설명하지 말고 글 자체를 메모에 넣는다.
  5. 이어받는 쪽의 다음 걸음과 먼저 열 파일.
- 다음 세션이 메모를 찾도록 한 줄을 기록한다:
  `python3 tools/now.py log --private "[<트랙>/state] handoff: <메모 경로>"`. 이 줄은 다음 세션이 받는 상태의
  최근 결정 자리에 나온다.
- 스레드에 서류철이 있으면 거기에도 다섯 줄을 덧붙인다(`AGENTS.md` 규칙 4). 메모는 이번 한 번의 넘김을
  나르고, 서류철은 스레드를 나른다.
- 이어받는 세션은 메모를 먼저 읽고 그다음 서류철을 읽는다.

*(Why: 대화 안에만 있는 것은 다음 세션에 닿을 다른 길이 없다. 메모가 없으면 주인이 앞 세션의 답을 손으로
붙여 넣게 된다. `decision:KIT-DR-027`.)*

<a id="events"></a>
## 결정과 사건 기록 (결정, 국면 변화, 발송·제출·공개)

- 기록 명령과 `--private` 기준은 `AGENTS.md` 규칙 2에 있다. 기록하면 NOW는 자동으로 다시 만들어진다.
- 트랙 정본 파일의 머리에 적힌 갱신일도 맞춘다. 맞추지 않으면 `python3 tools/now.py check`가
  [정본 낙후]로 잡는다. *(Why: 상태와 갱신 시점을 함께 두어야 낡은 정본을 알아볼 수 있다.)*

<a id="facts"></a>
## 개인 사실 (rec.py 원장)

- 조회 명령: `python3 tools/rec.py find <말>`, 상세 `show <id>`, 수정 이력 `audit <id>`, 정합 검사 `check`.
- 레코드를 고치거나 더하면 `python3 tools/rec.py hot`으로 핫셋을 다시 만든다. 핫셋은 생성물이라
  직접 고치지 않는다. *(Why: 손으로 고친 핫셋은 다음 생성 때 덮이고, 그 전까지 원장과 어긋난다.)*
- **녹취 전사 같은 출처와 사람의 기억이 부딪치면 어느 쪽도 조용히 따르지 않는다.** 출처와 함께 드러내
  사람이 판정하게 한다. 긴 인용과 관계의 방향은 확정 전까지 [불확실]로 표시한다.
  *(Why: 원문과 다른 귀속을 확정하지 않게 한다.)*

<a id="after-output"></a>
## 산출물 뒤 점검 (재편하거나 새로 만든 뒤)

- `python3 tools/linkcheck.py`로 깨진 참조 0개, `python3 tools/now.py check`로 어긋남 0개를 확인한다.
- 상태 문서를 고치면 머리에 갱신일을 적고, 같은 사실을 담은 다른 문서와 맞는지 확인한다.
  *(Why: 같은 사실의 사본들이 서로 다른 상태로 남지 않게 한다.)*
- **새로 만든 것에도 있는 검사기를 먼저 돌린다.** 저장소, 문서 묶음, 서류철을 새로 만들면 `linkcheck`,
  `now.py check`, `coherence` 순으로 그 산출물 안에서 돌린다. 새 검사기를 만들기 전에 있는 것을 쓴다.
  *(Why: 새 검사기는 기존 검사 범위를 자동으로 물려받지 않는다.)*
- **도구를 돌린 것과 도구의 출력을 읽은 것은 다른 일이다.** 종료 코드만 보고 넘어가지 않는다.
  *(Why: 도구가 성공적으로 끝난 것과 검사 대상이 정상인 것은 별개다.)*

<a id="files"></a>
## 파일 규약

- 새 작업 산출물의 파일 이름은 kebab-case에 `YYYY-MM-DD`를 붙인다. 코드와 도구 모듈은 그 언어의 관례를
  따르고, 밖에서 받은 원본 파일은 원래 이름을 지킨다. *(Why: 날짜가 든 이름이라야 찾고 정렬하기 쉽다.)*
- 복사해 붙여 보낼 메시지 본문은 `*-body.txt`로 따로 두고, 보낸 뒤 맨 위에 `[발송 완료 날짜]`를 적는다.
  *(Why: 보낸 본과 초안을 헷갈리지 않게 한다.)*
- 개인 대화 기록 같은 반입물은 [데이터 경계](#boundary)의 착지점 한 곳에 둔다.

<a id="outbound"></a>
## 외부 문안 작성 (10건 파일럿)

저장소 밖 사람이 읽거나 제출받을 글의 본문을 쓰거나 뜻을 바꾸기 전에, 아래 두 줄을 실제 값으로 채워
주인에게 보이는 작업 메시지에 먼저 낸다. 승인을 묻지 않고 계속한다. 두 줄은 보낼 본문에 넣지 않는다
(KIT-DR-008).

```text
문서 역할: 독자 / 승인자 / 목적(이 글이 성공했다고 볼 결과 하나)
정합 앵커: 트랙 정본 + 지금 파일시스템에서 확인한 실제 경로 + 제출·확정된 원문 경로
```

"지금 파일시스템에서 확인한 실제 경로"는 손으로 유지하는 색인이 아니라 `ls`나 `find`로 방금 본 경로다.
같은 작업에서 역할 셋이 그대로면 다시 내지 않고, 하나라도 바뀌면 다시 낸다. 내부 판독, NOW, 서류철,
분석 메모, 뜻을 바꾸지 않는 서식 수정은 이 절의 대상이 아니다. 그 다음 아래 순서로 쓴다 (KIT-DR-009).

1. **근거와 임무.** 실제 원문에서 사실을 확인하고, 받는 사람이 새로 알거나 해야 할 가장 좁은 결과
   하나로 정한다.
2. **닫기.** 예상되는 상대의 반응을 새 목적이나 질문으로 키우지 않는다.
3. **골격.** 짧은 글은 무엇을 요청하거나 알리는지만, 긴 문서는 주장과 근거의 순서만 먼저 정하고 고정한다.
4. **멈춤.** 골격의 각 항목을 한 번씩 펼친다. 쓰는 중 떠오른 새 목적, 질문, 자기평가는 더하지 않고
   마지막 항목에서 끝낸다.
5. **자세와 경제성.** 필요한 사실과 관계의 온도는 남긴다. 하는 일 없는 자기 해설, 미리 하는 변명,
   되풀이는 지운다. 화자를 평가하는 말 대신 사실을 둔다.
6. **받는 사람으로 다시 읽기.** 마지막에 받는 사람이 무엇을 가리키는지, 시간 순서, 원인과 결과, 다음
   행동을 되살릴 수 있는지 읽는다. 지우다가 필요한 연결이 끊겼으면 되살린다.

담백함은 짧음이 아니다. 필요한 논리와 온기는 남기고 두 번째 임무와 자기평가를 싣지 않는 것이다.
금지어 목록과 길이 상한은 두지 않는다. 예외는 `AGENTS.md` 규칙 5의 em-dash 금지 하나다. em-dash는
낱말이 아니라 AI가 쓴 글로 읽히게 만드는 부호라서 따로 둔다. 출처를 잘못 읽은 문제는 문체로 덮지 않고
먼저 사실을 바로잡는다.

<a id="boundary"></a>
## 데이터 경계 (방향은 인스턴스마다 다르다)

이 절을 다른 인스턴스에 그대로 옮기지 않는다. 어느 쪽이 안이고 어느 쪽이 밖인지는 인스턴스의 정체
(`system/memory-config.json`의 `instance.context`)에 달렸다. 개인 워크스페이스의 규약을 회사
워크스페이스에 복사하면 방향이 뒤집힌다. 들여오기를 막아야 할 자리에서 내보내기를 막게 된다.

**방향과 상관없이 참인 원리 셋.**

1. **들여오기는 사람이 한다.** 에이전트는 경계 밖의 자료를 가져오지 않는다.
   *(Why: 들여올지는 사람이 판단하고 격리는 에이전트가 맡는다. 순서를 바꾸면 판단이 빠진다.)*
2. **들여온 자료는 한 곳에 둔다.** 추적되지 않는 `_private/` 아래 폴더 하나이고, 어느 폴더인지는
   `system/instance-rules.md`에 적는다. 세션 안에서 읽고 회상하는 것은 되고, 커밋·인용·외부 전송은
   안 된다. 일꾼 실행 기록(`_private/work/runs/`)은 들여온 자료가 아니라 생성물이라 여기에 들지 않는다.
   *(Why: 흩어지면 어느 파일이 어느 등급인지 아무도 모르게 된다.)*
3. **커밋되는 문서에는 추상적인 내용만 둔다.** journal, NOW, 서류철, 아티팩트에 실측 숫자, 내부 코드명,
   원문 인용, 스크린샷을 싣지 않는다.
   *(Why: 커밋된 것은 원격으로 나가고, 나간 것은 지워도 남는다.)*

**이 인스턴스의 안과 밖은 `system/instance-rules.md`에 쓴다.** 최소한 세 가지를 적는다. 무엇이 들여온
자료인가, 어디에 두는가, 어느 원격으로도 나가면 안 되는 것은 무엇인가. `tools/doctor.py`의 경계 검사가
그 선언을 기계적으로 집행한다.

<a id="lenses"></a>
## 사고렌즈

- [렌즈 목록](lenses/README.md)에서 관점을 고르고 그 렌즈 파일의 정의를 읽는다. 목록의 렌즈는 출발점이며
  그 자리에서 만든 관점도 같은 기준으로 고른다.
- 주인이 자기 자신에 대해 단언하면, 있는 근거를 먼저 확인한 뒤에 해석을 굳힌다. 이 확인은 주인이 밝힌
  경험을 무시하거나 주인 대신 선호를 정해도 된다는 뜻이 아니다.
- [딥패스 기록 계약](deep-pass.md#recording)에 따라 인스턴스의 `_private/deep-pass/ledger.md`에
  판정, 쓴 관점, 정정의 출처, 이후 관측을 남긴다. 다른 보호된 위치를 쓰려면 인스턴스 규칙에 정한다.
  원장이 없으면 [빈 템플릿](../templates/deep-pass-ledger.md)을 복사하고, 있으면 이어 쓴다.
- 실제 사례는 추적되는 렌즈·딥패스 문서·템플릿에 쓰지 않는다. 사용 횟수는 관찰값이지 효과나
  폐기의 근거가 아니다. 로컬 기록의 백업은 업스트림 엔진 업데이트와 따로 한다.

<a id="browser"></a>
## 브라우저로 외부 시스템 다루기

- **되돌릴 수 없는 버튼은 사람이 누른다.** 제출, 발송, 결제, 서명. 에이전트는 입력과 준비까지 한다.
  *(Why: 되돌릴 수 없는 행동은 주인 몫이다. `AGENTS.md` 규칙 5와 같은 이유다.)*
- **업무·금융 포털은 자동 저장된다고 가정한다.** 둘러보려고 누른 것도 데이터를 저장할 수 있다.
  **읽기가 기본이고, 클릭과 입력은 지시가 있을 때만 한다.** *(Why: 둘러보기와 저장이 화면에서 구별되지 않는다.)*
- 폼의 빈칸이나 적힌 값은 누락이 아니라 **예전에 내린 판정**일 수 있다. 채우기 전에 관련 정본에서
  그 판정의 근거를 먼저 찾는다(`AGENTS.md` 규칙 3). *(Why: 빈칸을 채우면 지난 판정을 말없이 뒤집을 수 있다.)*
- 로그인과 비밀번호는 사람이 직접 한다. 에이전트는 자격 증명을 입력하지 않는다.
  *(Why: 자격 증명이 대화 기록과 로그에 남지 않게 한다.)*

<a id="memory"></a>
## 기억 시스템 운용 (상세: `system/PRD-session-memory.md`)

- 회상: `python3 tools/recall.py find "질의"`. 결과를 통째로 붓지 말고 지금 질문에 묶어 몇 줄로 쓴다.
  있다고 아는 원문을 회상이 못 찾으면 `python3 tools/now.py log "[system/lesson] 회상 실패: <질의>"`로
  남긴다. 같은 기록이 세 번 쌓이면 세 번째를 남긴 세션이 주인에게 의미 기반 검색(임베딩)을 더할지
  다시 따져 보자고 알린다.
- 정리: `/garden`은 [수동, 보고만 하는 감사](../../system/design-memory-runtime.md#manual-garden)다. 그 뒤 실제로 고치는
  일은 세션이 맡고, 인스턴스가 명시적으로 맡긴 범위를 따른다. **주인에게 판정을 묻는 것은 구조, 정책,
  개인 사실, 동결 구역에 관한 것뿐이다.** 기계적이고 위험이 낮은 정리(수치 정정, 갱신일, 본문을 경로로
  바꾸기, 도구 버그)는 에이전트가 하고 나중에 보고한다. *(Why: 작은 결정까지 올리면 주인의 주의를 낭비한다.)*
- 곁가지 아이디어는 실행하지 않고 journal에 `idea`로 적어 두었다가 정기 검토에서 한꺼번에 다룬다.
  *(Why: 떠오를 때마다 실행하면 일의 범위가 불어난다.)*

## 이 인스턴스만의 의식

이 파일은 업스트림 소유다. `git pull`이 덮어쓰므로 여기에 이 워크스페이스 전용 규약을 쓰면 다음
업데이트에 사라지거나 충돌한다. 인스턴스 고유 의식은 `system/rituals.local.md`에 쓴다. Git 밖이라 안전하고,
없으면 아직 없는 것이다. 이 문서를 읽을 때 그 파일이 있으면 함께 읽는다. 데이터 경계 선언은
`system/instance-rules.md`가 맡는다.
