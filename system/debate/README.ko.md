# 런타임 간 토론

다른 런타임으로 결정의 가정과 근거를 공격한다. 소유자는 도구 사이의 전령 대신 해결된 추천이나
준비된 미해결 결정 하나를 받는다. 토론은 제안을 개선할 수 있지만 합의가 독립 검증은 아니다.

이 README는 공유 엔진 정책이다. 발주문·사례 기록·실행 결과는 인스턴스에 속한다.
기본 ignore 규칙은 이 README와 번역본만 추적하고 주변 토론 파일은 추적하지 않는다.
ignore는 일반적인 Git 포함을 막을 뿐, 내용을 모델로 전송할 권한을 주지는 않는다.

## 왕복 준비

1. 결정·가장 강한 대안·추천을 바꿀 조건을 적는다.
2. 실제 파일 경로를 확인한다. 질문에 답하는 데 필요한 현재 계약과 근거만 고른다.
   전체 세션·서류철 묶음·개인 코퍼스를 기본 첨부하지 않는다.
3. 발주 전에 인스턴스 데이터 국경을 확인한다. 프롬프트·경로·도구 읽기가 각각 정보를 노출할 수
   있다. 허용된 자료만 쓴다. 필요하면 비공개 원문 없는 일반 기술 질문으로 바꾸거나 검토 불가로
   남긴다.
4. [라운드 템플릿](../../templates/debate-round.md)을 `system/debate/_p_review.md` 같은 ignore된
   인스턴스 발주문으로 복사한다. 추적되는 템플릿은 비워 둔다. 토론 기록은 `_private/debate/` 같은
   보호된 인스턴스 위치에 두고 작업자 실행 기록을 연결한다.
5. 각 쓰기의 소유자를 정한다. 검토 발주는 코드·정책·원문 증거 수정의 위임이 아니다.

재사용 템플릿은 전략 가정 공격·실제로 적용한 관점·중요 발견의 근거·직전 라운드에 대한 응답·
안 읽었거나 접근할 수 없었던 자료의 공개를 요구한다. "판정을 바꿀 발견 없음"과 비판의 기각도
정당한 결과다.

## 발주와 런타임 경계

기본은 새로 시작하는 일회성 작업자다. 셸의 특수문자가 데이터로 남도록 발주문을 파일에 쓴다.
인스턴스 루트에서 원하는 런타임을 고른다.

```bash
python3 tools/fresh_worker.py --runtime claude system/debate/_p_review.md
python3 tools/fresh_worker.py --runtime codex system/debate/_p_review.md
```

예시 경로는 실제로 준비한 발주문으로 바꾼다. 검토자 수를 늘리려고 둘 다 실행하지 말고 선택한
명령을 쓴다. `bash tools/ask_codex.sh PROMPT_FILE`은 새 Codex 호출을 위한 호환 진입점이다.
명시적으로 요청한 resume은 다른 작업이며, 실패를 숨기고 새 세션으로 폴백해서는 안 된다.

정확한 권한·영수증·저장 계약은 [작업자 계약](../PRD-session-memory.md#105-fresh-bounded-worker-kit-dr-007)이
소유한다.

- Claude의 도구는 읽기 전용 `Read`·`Glob`·`Grep`이다. 수정안을 낼 수 있지만 적용하거나 셸 검사를
  돌릴 수 없다. 쓰기나 셸 실행을 필수로 요구한 뒤 응답만 보고 완료를 추정하지 않는다.
- Codex는 workspace-write 샌드박스를 쓴다. 검토 전용 지시는 작업 범위이지 운영체제 수준의 읽기
  전용 보장이 아니다. 사용 가능한 범위 검사를 쓰고 실제 영향을 확인한다.
- 작업자는 호출자의 대화를 상속하지 않고 훅에 현재 상태를 의존하지 않는다. `AGENTS.md`와 필요한
  정본을 명시한다. NOW가 필요하면 데이터 국경을 지키며 public/local 두 표면을 명시한다. 읽을 수
  없는 local overlay는 unavailable이지 없음이 아니다.
- 두 adapter는 커넥터·웹·명령 네트워크·플러그인·fan-out을 끈다. 이 제한이 금지된 자료의 모델 입력을
  허용해 주지는 않는다.
- 실행기는 발주문·이벤트 전사·최종 결과·메타데이터·내용 해시를 `_private/work/runs/`에 남긴다.
  호출자는 제한된 영수증을 받는다. 검토자가 무엇을 봤고 실행했고 확인했는지 주장하기 전에
  결과와 관련 근거를 읽는다.

끝나거나 중단을 기록할 때까지 실행 핸들을 유지한다. 작업자는 스케줄러를 소유하지 않으며,
백그라운드 프로세스 자체는 알림 장치가 아니다. 호출 런타임의 대기·완료 기능을 쓰고 결과를 확인한다.
실제 예약 경로 없이 나중에 확인하겠다고 약속하지 않는다.

## 토론 보존

호출자가 완료된 라운드를 인스턴스 토론 기록에 이어 쓰거나 보존된 결과를 링크한다. 다른 참가자의
원래 응답을 고치지 않는다. 요약은 요약으로 표시한다. 정정과 반론은 새 항목이며 확인 가능한 실제
런타임과 모델을 함께 남긴다.

실행·상태 주장에는 범위가 있는 확인 가능한 산출물·명령 결과·내용 해시를 붙인다. 제안한 검사는
실행한 검사가 아니다. 논문의 주장·로컬 관측·인상은 근거의 역할이 다르다. 검토자의 확신을 증거로
바꾸지 말고 각각의 한계를 쓴다.

반박 전에 허용된 해당 문장을 인용하고 직접 답한다. 구체적인 영향과 최소 정정을 설명한다.
다른 모델 계열은 다른 오류를 드러낼 수 있지만 근거의 독립성을 보장하지 않는다. 같은 계열의 검토는
독립된 뒷받침으로 세지 않는다.

## 종료

첫 응답은 자문이지 완료된 왕복이 아니다. 가장 강한 논점에 답하고 그 반론에 대한 응답을 받는다.
한 번 더 돌리기 위해 반론을 만들지는 않는다.

- 중요한 판정이 바뀌고 다음 라운드에 구체적인 미지나 새 근거가 있으면 계속한다.
- 왕복 뒤 결정에 영향을 줄 이견이 남지 않으면 수렴으로 기록한다.
- 관련된 새 근거를 더 얻을 수 없으면 멈추되 미해결 이견과 수렴을 구분한다.
- 한도나 데이터 국경 때문에 막히면 차단 또는 판정 불가로 기록하고 필요한 관측을 남긴다.

라운드 수로 품질을 재지 않는다. 채택한 정정과 기각한 정정을 모두 보존한다. 남은 차이를 소유자가
정해야 하면 준비된 결정 하나와 답에 따라 바뀌는 것을 제시한다.

## 집행과 관측

수렴하거나 소유자가 판정한 뒤 위임된 작성자가 합의한 변경을 적용한다. 기존 구현 예산과 보호
영역은 그대로다. 현재 기준판과 최종 변경을 다시 확인하고 관련 검증을 실행한 뒤 실제 관측을 남긴다.
발송·커밋·푸시는 기존 위임 요건을 따른다. 토론 자체는 권한을 부여하지 않는다.

채택한 정책은 해당 인스턴스 또는 킷의 결정 기록으로 승격한다. 비공개 사례와 로컬 파일럿 일정은
공유 엔진 문서에 넣지 않는다. 후속 실행과 소유자 피드백을 처음 결정에 연결한다. 검사 통과와 설계
합의는 실제로 일이 좋아졌다는 관측과 별개다.
