<a id="purpose"></a>
## 1. 목적과 실패 비용

사용자가 과거를 다시 설명하거나 같은 오류를 다시 고치지 않아도, 에이전트가 현재 의도와 근거를 이어 받아 일을 완료한다. 저장량·검색 횟수·규칙 준수율은 이 목적을 위한 중간 관측이다.

막아야 할 실패는 이미 결정한 것을 이유 없이 다시 제안하는 것, 확인 가능한 근거를 읽지 않고 단언하는 것, 추론을 사실로 굳히는 것, 정정을 기록하고도 다음 행동에 반영하지 않는 것이다. 정확한 기록이 있어도 조회·해석·합성에서 실패할 수 있으므로, 기록뿐 아니라 실제 응답과 행동까지 검증한다.

사용자는 정기 정리 작업을 맡지 않는다. 에이전트가 기록·조회·갱신을 수행하고, 사용자가 결정해야 하는 미지만 짧게 드러낸다. 이미 답이 있는 확인 질문을 반복하는 것도 비용으로 센다.

<a id="authority"></a>
## 2. 주장의 원점·현재 효력·적용 범위

파일 종류 하나로 모든 주장에 권위를 부여하지 않는다.

| 알고 싶은 것 | 우선 확인할 근거 | 함께 확인할 것 |
|---|---|---|
| 누가 무엇을 말했나 | 원문 메시지·대화 로그·음성 | 화자, 시간, 원문과 전사·요약의 구분 |
| 무엇을 하기로 결정했나 | 명시적 사용자 결정, 확정된 DR와 decision 사건 | 탐색 발언인지, 이후 변경·철회됐는지 |
| 지금 무엇이 진행 중인가 | 해당 범위의 최신 정본과 실행 증거, 합친 NOW | 실제 원본 신선도, local 상태의 이용 가능 여부 |
| 왜 그 결론에 도달했나 | 해당 스레드 서류철과 연결된 원문·판정 | 기각 이유, 남은 미지, 결론의 조건 |
| 실제로 실행·검증됐나 | 해당 실행의 결과·로그·관측 | 대상 버전, 방법, 관측 시각, 미관측 범위 |

사용자의 결정·선호·계획·정정은 사용자의 발화가 원점이다. 에이전트 문서는 이를 대체하지 않는다. 원문에 가장 가깝다는 것은 귀속 근거가 강하다는 뜻이며, 오래된 원문이 최신 결정을 이긴다는 뜻은 아니다.

상충하는 기록은 조용히 최신 파일 하나로 덮지 않는다. 명시적 변경과 대체 관계로 해결할 수 있으면 연결하고, 해결되지 않으면 충돌과 판단에 필요한 근거를 드러낸다. 현재 사용자 지시가 분명하면 이미 위임한 결정을 다시 승인받지 않는다.

<a id="record-lifecycle"></a>
## 3. 기록의 생성·정정·대체·보존

원문은 보존하고 해석은 고칠 수 있어야 한다. 기록의 정정은 무엇이 무엇을 대체했는지 남기며, 철회 기록을 지워 과거의 잘못된 방향이 다시 살아나게 하지 않는다. 기존 동결 영역은 참조만 한다.

사실 원장은 한 레코드에 하나의 주장을 담는다. 내용·원점 위치·파생 경로·화자·날짜·주제·상태·대체 관계가 있어야 한다. 원점이 유실됐으면 그 공백을 표시한다. 사실성(확정·전언·추론·미해결)과 효력(결정·대체·철회)은 다른 개념이다. 현 저장 형식을 바꾸기 전에도 둘을 혼동하지 않는다.

정정·새 원점 사실·결정·상태 변경은 발생한 턴에 기록한다. 세션 종료가 유일한 기록 시점이어서는 안 된다. 안정된 문서를 모두 원자 기록으로 다시 만드는 것은 요구하지 않는다. 어떤 기록을 적극 추출할지는 휘발성과 향후 결정에 미치는 영향을 보고 정한다.

`결정됨`은 새 근거 없는 반복 제안을 막는다. 사용자 재검토 요청, 적용 조건 변화, 반증이 생기면 이전 이유를 보존한 채 다시 판단할 수 있다. 재검토 자체를 위반으로 취급하지 않는다.

<a id="retrieval"></a>
## 4. 조회와 모름의 처리

| 행위 | 필요한 동작 |
|---|---|
| 일반 설명·잡담 | 관련 없는 개인 기록을 자동으로 불러오지 않는다 |
| 기록에 관한 구체 사실 단언 | 원점 또는 그 주장을 뒷받침하는 기록을 확인한다 |
| 행동·전략 제안 | 현재 제약과 이미 수행·결정된 내용을 확인한다 |
| 문서 작성·갱신 | 근거와 현재 의미를 확인하고 충돌을 검사한다 |

현재 대화에 명시된 사실을 또 묻지 않는다. 기록으로 확인 가능한 것은 먼저 조회하고, 남은 미지가 결과를 바꿀 때만 사용자에게 묻는다.

검색은 키워드·주제·상태·인물·기간을 지원하고, 태그 누락에도 찾을 수 있는 전문 검색 경로를 유지한다. 감사 사슬은 주장→파생물→원점 위치로 연결돼야 한다. 작은 핫셋은 중요한 결정·철회·현재 사실·미해결의 존재를 알려주고, 전체 자료를 대신하지 않는다. 핫셋에는 상한과 강등 조건이 필요하다.

검색 결과가 없다는 것은 검색한 범위에서 못 찾았다는 뜻이다. 원문 없음, 접근 불가, 파서 누락, 검색어 불일치와 구별한다. 근거가 없거나 낡거나 상충하면 그 범위를 모른다고 말하고 추론을 사실로 채우지 않는다. 정직한 모름도 남은 유용한 작업을 중단하는 이유가 되지는 않는다.

<a id="boundaries"></a>
## 5. 데이터 경계와 전달

파생 기록·요약·시각화는 원자료의 비공개·동결·외부 전송 제한을 상속한다. Git 추적 여부, 모델로 전송해도 되는지, 외부 사람에게 보내도 되는지는 별도 판정이다. 공개 경로에 썼다는 이유로 공개 가능한 내용이 되지 않는다.

개인 사례와 실행 원문은 private에 두고, 공개 문서는 일반 계약과 공개 가능한 검증만 담는다. 킷으로 내보내는 것은 일반화된 엔진 계약이며, 인스턴스의 개인 이력이나 위임 권한을 그대로 옮기지 않는다. 구체 불가침·발송·커밋 권한은 `AGENTS.md`와 유효한 명시 위임을 따른다.

사용자가 결과를 읽거나 행동해야 할 때는 실제 이용하는 기기·표면에서 전달됐는지 확인한다. 파일을 만들었거나 링크를 적었다는 사실만으로 읽기 가능한 전달을 완료했다고 하지 않는다.

<a id="acceptance"></a>
## 6. 사용자 결과로 검증하기

기존의 '20문 오답 0'은 유지하되 **답할 수 있는 20개 질문을 모두 모른다고 해서 합격시키지 않는다.** 정답에 필요한 자료를 준비한 새 세션 시험에서 다음을 따로 보고한다.

1. 답할 수 있는 질문: 근거 있는 정답, 오답, 불필요한 모름의 수.
2. 원문이 없거나 현재 답이 없는 질문: 모름과 근거 없는 단언의 수.
3. 정정·철회·시간 충돌: 이전 주장을 반복했는지, 현재 효력을 복원했는지.
4. 실제 작업: 이전 결론·제약을 반영해 사용자의 다음 판단이나 행동을 도왔는지.

기존 목표인 재제안 0, 임의 주장 30초 내 원점 추적, 한 문장으로 가능한 정정, 같은 오류의 비재발, 체감 지연 없는 대화는 폐기하지 않는다. 평가 기간·사례·분모·관측 주체와 함께 측정한다. 에이전트가 측정하지 않은 체감이나 사용자 만족은 UNKNOWN이다.

정정 횟수가 줄거나 응답이 없다는 사실은 관측 기회·노력의 감소 때문일 수도 있으므로, 그 조건을 함께 보고하고 침묵을 성공으로 세지 않는다. 일부 측면의 긍정을 전체 과업 성공으로 확대하지 않는다.

도구가 동작했는지, 필요한 근거를 찾았는지, 세션에 주입됐는지, 응답·행동이 달라졌는지, 실제 결과가 좋아졌는지는 다른 주장이다. 한 단계의 PASS를 뒤 단계의 PASS로 재사용하지 않는다.

정정 기록에는 원인 가설과 함께 실제로 어디서 놓쳤는지, 누가 발견했는지, 다음 실행에서 재발했는지를 남긴다. 기존 I-1~I-5/A-1~A-5 분류는 과거 비교용으로 보존할 수 있지만, 분류 칸을 채운 것을 회복으로 세지 않는다. 별도 사용자 입력 양식은 만들지 않는다.

<a id="unmet"></a>
## 7. 미충족과 재검토

새 세션 20문·30초 감사·정정 비재발·대화 지연은 각 인스턴스의 현재 버전에서 검증한다. 자동 핫셋 로드, 전 유형 정정 telemetry, append-only 기록의 강제 여부도 종단 간 증거가 없으면 UNKNOWN이다. 설치 성공이나 다른 인스턴스의 관측을 이 검증의 통과로 세지 않는다. 미충족·미검증 요구는 삭제하지 않고 `design-memory-runtime.md#verification`의 절차로 확인한다.

새 저장 형식·임베딩·그래프·규칙 자동 승격은 실제 실패와 비교 시험이 필요하다. 문서 수나 사용 횟수가 늘었다는 이유로 도입하지 않는다. 전수 검토가 과업이면 전수 읽기를 허용하되, 읽은 범위와 이해·검증 범위를 구별한다.
