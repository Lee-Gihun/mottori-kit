# Large jobs

For the moment before a large job is handed over, whether a person is ordering it from an agent or an
agent is about to dispatch workers. Large means reading everything in a body of material, a large
parallel run, or work that will outlive this session. A small conversation or a one-file edit does not
need this.

A machine can read all of it, so how much gets read is no longer the limit. The limits are how much
the person can take in, and whether the question is one whose answer can be measured. So do not shrink
the job to what a person could have read. Decide first how the result will be judged.

Before the order goes out, answer six questions. If you cannot answer one, the job is not ready.

1. **What does it measure?** For a reading job, at least one number should come out that is true of
   the whole body of material: every paper, every file, every record in scope. A count of items
   processed is not one. For a building job, the checks that must pass, written before the work starts.
2. **How much can the person take in?** This sets the shape of the output, not how much is read.
3. **Where could it be wrong?** Each item of the output carries a field that says how you would notice
   if that item were wrong. An output that cannot be caught wrong cannot be trusted either.
4. **Where does it resume after an interruption?** Which file holds the progress, and which command
   works out from that file what is left.
5. **How will success be known?** What the person will do differently because of the result. The first
   check comes at the end, when they mark which items were useful.
6. **Can each number be traced?** Its unit, what it counts, the period, the definition, and where the
   raw data is.

An order that answers them, as the person would write it:

```text
Read all of [material] and measure [the property].
Do not reduce the breadth. Render the output so that I only have to take in [amount].
For each item, write how I would notice if it were wrong.
For each number, keep its unit, what it counts, the period, the definition and where the raw data is.
Keep progress in [file], and build a command that works out from it what is left.
When it is done I will look at [N] items and mark which were useful. Rerank with that.
```

While it runs:

- Write each item as it finishes. Results collected and written at the end are lost to one
  interruption.
- Tell each worker what it may change, what it may only read, what it must deliver and what it must
  not touch.
- The person does not approve a reading list at the start. They judge results at the end: "which of
  these changed your work?"

When it ends, close the job: one page at the top of the job's folder that says what to keep and what
may be deleted.
